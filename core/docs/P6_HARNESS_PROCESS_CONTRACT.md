# P6 Harness Compatibility & Process Integration Contract

Status: implementation baseline for P6.

## Boundary

Project Factory owns project semantics, the canonical Agent Contract, Blueprint/Lock/Evidence, and verification truth.
Harnesses own their agent loop, context/session handling, permissions, sandbox, and native subagent behavior.
Spec Kit owns its process artifacts and skills when installed; Project Factory does not copy or fork Spec Kit implementation.

## Canonical contract

The canonical project-agent contract lives at:

`.project/contract/agent-contract.md`

Harness context files are generated byte-for-byte from this file. P6 supports:

- Codex adapter -> `AGENTS.md`
- Claude Code adapter -> `CLAUDE.md`

A Project Lock stores the canonical SHA-256 plus every harness context SHA-256. Restore verification fails if any context diverges.

## Runtime claim boundary

Context-file parity is not a live harness execution test. P6 therefore records harness context compatibility as `PARTIALLY_VERIFIED` unless a future stage performs a real end-to-end harness session.

## Spec Kit process provider

P6 pins its public integration contract to Spec Kit v1.0.1. The optional plan is:

1. `specify init --here --integration <default> --script py`
2. `specify integration install <additional> --script py` for additional multi-install-safe harnesses
3. `specify integration status`

The P6 default harness pair is Codex + Claude Code. Spec Kit v1.0.1 declares both as skills-based and multi-install safe, using `.agents/skills` and `.claude/skills` respectively.

P6 intentionally does **not** install Spec Kit's `agent-context` extension because Project Factory owns `AGENTS.md`/`CLAUDE.md`. Spec Kit's own architecture separates integration skill installation from the opt-in agent-context extension, so this avoids context-file ownership collision.

## Modes

- `plan`: write an exact process plan and evidence `PLANNED_NOT_INSTALLED`; do not create `.specify/`.
- `execute`: require an exact supported `specify` runtime version before mutation, execute only trusted argv lists (no shell string), and verify `.specify/integration.json` plus expected skills directories.

The current build environment has no real `specify`, Codex CLI, or Claude Code CLI. Real runtime compatibility therefore remains unverified in P6. A deterministic contract test double validates adapter command sequencing and evidence behavior without being misrepresented as upstream runtime evidence.

## Upstream preservation

- No Spec Kit source is vendored or modified.
- No Codex or Claude Code source is vendored or modified.
- Product-specific IDs and context paths live in adapter registries/modules, not Factory Core.
